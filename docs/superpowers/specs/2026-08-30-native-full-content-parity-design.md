# 原生小程序全量内容等价与信息架构改造

## 目标

将 `cdms-weixin` 的医生端和患者端业务页面改造成与现有 H5 内容和业务行为等价的原生小程序页面。原生页面允许针对移动端重新排版，但不得减少字段、列表列、详情信息、编辑项、操作、校验、接口载荷或状态反馈。

本次同时修复三个已确认问题：

- 患者 360 当前只展示摘要，缺少 H5 的六个完整模块及详情操作。
- 统计和监测趋势当前以数字/行列表展示，改为原生 Canvas 图表。
- 首页业务入口重复、分散，重整为按角色和任务组织的单一主工作台。

AI 报告属于可用但存在 BUG 的功能，不得隐藏或永久标记为不可用；需要修复小程序对后端 SSE 生成接口的调用和展示链路。

## 约束与事实来源

- H5 `frontend/src/views` 与 `frontend/src/components` 是字段、流程、选项、状态和接口行为的参考基准。
- `cdms-weixin` 原生患者工作台的颜色、圆角、卡片、表单和信息层级是视觉基准。
- 现有服务端接口、权限、数据表和设备协议优先复用，不改变服务端业务规则。
- 所有 ID 在小程序中按字符串处理，不进入 URL 的敏感患者信息、令牌或报告短时地址。
- 图表只使用服务端返回的真实数据；无数据时显示空态，不生成模拟点。
- 不使用 WebView/H5 承载正式业务页面；公开建档问卷仍是唯一外部 H5 例外。

## 页面内容等价范围

### 患者 360

保持 H5 的六个 Tab：综合信息、筛查信息、评估信息、随访记录、检查检验、转诊信息。

- 综合信息展示头像/姓名、风险与机构标签、性别、年龄、手机号、证件号、身高、体重、BMI、地址、吸烟状态、吸烟情况、GOLD、CAT、mMRC、FEV1%、最新筛查/评估/随访/检查统计。
- 筛查列表保留日期、总分、风险等级、咳嗽、呼吸困难、来源和明细查看。
- 评估列表保留日期、类型、CAT、mMRC、GOLD、ABE、评估医生和明细查看。
- 随访列表保留日期、方式、CAT、mMRC、下次随访和详情查看；详情结构化展示随访字段、用药依从性、备注、体格/生活方式快照和 COPD 快照，不以原始 JSON 代替。
- 检查检验保留时间、类型、报告号/设备、结果、报告预览/下载；诊断附件全部列出。
- 转诊列表保留发起时间、转出机构、接收机构、方向、状态和原因。
- 报告短时访问地址只在点击预览/下载时获取并直接交给微信预览或下载能力。

### 患者档案与编辑

患者详情页保留 H5 的档案头部、风险/GOLD 标签、基本信息、慢阻肺摘要、随访统计、监测摘要和全部快捷操作。编辑状态不得只显示少量摘要字段，必须覆盖 H5 `PatientAdd.vue` 的基础档案、联系方式、地址、吸烟/肺功能和 COPD 相关字段；新增、编辑、重复校验、保存成功/失败和返回流程保持一致。

### 列表、详情与业务页

逐页对照 H5 完成患者列表、随访列表/填报/详情、监测摘要/趋势/提醒、标准报告/AI 报告、历史记录、消息和统计页面。每个页面必须保留 H5 的字段、筛选、排序、分页/加载更多、详情、编辑、删除或确认操作（如 H5 存在），不使用单一摘要卡片替换完整列表。

### 随访填报

保持 H5 四步结构：随访信息与评估、体格与辅助检查、生活方式与用药、专科与总结。恢复日期/时间选择、单选/多选卡片、数字输入范围、动态列表、条件字段、图片预览/删除、草稿、编辑和提交。

- CAT 八项、mMRC、CAT 分数、mMRC 评级和 BMI 的计算/展示与 H5 一致，服务端仍是最终权威。
- 家庭氧疗与流量/时长、药物“其他”、调药建议等联动字段与 H5 一致。
- 步骤切换和正式提交按 H5 顺序校验，并将用户带回首个错误步骤。
- `examLifestyleSnapshot`、`copdInfoUpdate`、照片和普通字段按 H5 数据结构生成载荷。

## 图表方案

新增通用原生 `trend-chart` 组件，使用微信 Canvas 绘制，不引入 WebView 或 H5 图表库。组件接收标题、单位、点位、颜色、空态和时间范围，负责坐标轴、网格线、折线/柱状图、最新值和触摸点提示；业务页面只负责映射服务端数据。

- 统计页：随访趋势折线图、风险等级分布柱状图、随访类型分布图；数字卡片保留为摘要，不再承担趋势展示。
- 监测页：血氧、心率、步数、睡眠时长四张趋势图，保留 7 天/30 天切换、最新值、单位、时间和告警列表。
- 图表点位排序、缺失值处理、时间范围切换和空态必须有单测；图表不可用时仍显示完整可读的数据摘要。

## 首页信息架构

- 医生首页收敛为“医生工作台”：核心统计、待随访/重点风险患者、统一搜索筛选、消息提醒和一个紧凑的次级导航区。
- 患者管理、随访、监测、报告、患者 360 等不再在首页重复铺设多组入口卡片；从患者详情和统一导航进入。
- 设备相关入口不得丢失。设备中心作为底部菜单的固定主入口保留，进入后承载设备绑定、连接、同步、健康历史、运动、固件升级、MFA-1、Sunvou 报告和体脂秤等能力；首页只展示设备摘要和最近同步状态。
- 患者首页只保留个人健康概览、设备摘要/同步、趋势/历史和消息，不混入医生管理入口。
- 角色切换保留，但切换后进入对应角色唯一主工作台。
- 业务入口按照“当前任务优先”排序，不展示已在当前页面重复出现的入口。

底部菜单按“主工作台 + 高频业务 + 设备固定入口”组织。医生端至少提供工作台、患者、统计、设备四个一级入口；患者端至少提供首页、健康/随访、消息、设备四个一级入口。需要患者上下文的随访、监测、报告和患者 360 从患者详情或患者业务页进入，不再复制成大量一级菜单。底部菜单切换不得清除登录状态、当前角色或设备绑定状态。

## AI 报告修复

后端生成接口返回 `SseEmitter`，协议事件为 `delta`、`done`、`error`。当前小程序生成方法通过普通 JSON `wx.request` 调用，无法可靠消费流式事件，这是当前不可用的首要根因。

小程序新增原生流式请求适配：开启微信分块回调，缓存跨分块内容，按 SSE/JSON 边界解析事件；`delta` 追加内容，`done` 保存完整报告，`error` 显示可重试错误。保留 H5 的已有报告读取、重新生成、医生批注、确认和免责声明；Markdown 采用安全的原生文本分段渲染，不执行服务端 HTML。

AI 报告入口保留并恢复可用状态。患者 AI 报告和机构 AI 报告分别校验患者/机构上下文；生成中禁止重复提交，断线可重试，旧流事件不能覆盖新一轮结果。

## 错误、加载和权限

- 所有生命周期异步加载必须捕获异常，不产生未处理 Promise rejection。
- 页面区分加载、空数据、网络失败、无权限、资源不存在和会话失效，并提供对应重试或返回操作。
- 只有用户明确退出登录才清除持久会话；普通网络错误不清除登录状态。
- 医生患者上下文只使用受控的应用内一次性上下文，不信任伪造 query 中的患者 ID。

## 测试与验收

新增或更新以下测试：

- H5/小程序字段与页面模块覆盖矩阵，确保内容不减少。
- 患者 360 六 Tab、结构化详情、报告预览/下载和附件展示。
- 患者档案新增/编辑、重复校验、完整载荷。
- 随访四步表单、联动字段、逐步校验、草稿、照片和提交载荷。
- 统计/监测图表数据映射、范围切换、空数据和缺失点。
- 首页角色入口收敛和不重复展示。
- AI SSE 分块解析、`delta/done/error`、重试、确认和防旧流覆盖。
- 全量 Node 测试、JS 语法检查、路由/组件静态检查、安全扫描和 `git diff --check`。

验收标准：微信开发者工具可导入并完成医生登录、选择患者、查看患者 360 六模块、编辑档案、完整填报随访、查看监测/统计图表、查看标准/AI 报告、完成报告确认；关键异常均可恢复。真机操作由验收方执行，当前环境只负责达到可联调状态。

## 实施顺序

1. 建立 H5/小程序内容字段矩阵和失败测试。
2. 抽取原生通用信息网格、数据表、详情抽屉、图表和表单字段组件。
3. 完成患者 360、患者档案/编辑和患者列表内容等价。
4. 完成随访全量填报和详情流程。
5. 完成监测、统计图表、报告/AI 报告和首页信息架构。
6. 全量验证、提交并推送隔离分支；验收通过后再合并主干。
