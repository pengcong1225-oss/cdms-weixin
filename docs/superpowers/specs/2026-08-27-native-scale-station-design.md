# 原生小程序体脂秤轮测场次设计

## 目标

在同一个微信原生小程序中，为医生提供花潮 AiLink 身高体脂秤轮测场次，为已建档患者提供登录后扫码签到能力。系统必须支持多名患者依次测量，避免医生在全机构患者中搜索，也避免体脂数据串档。现有指环 BLE、绑定、同步和真实测试链路不得改变。

## 已确认边界

- 医生端和患者端均使用原生小程序页面，不使用 H5 或 WebView 承载体脂秤业务。
- 体脂测试签到只允许已登录且已关联 `patientRef` 的患者。
- 患者身份完全由服务端根据访问令牌派生；签到请求不得信任客户端提交的患者 ID、机构 ID、姓名、手机号或身份证号。
- 未关联患者档案时不得加入候测队列。页面显示通用建档问卷地址并提供复制按钮。
- 通用问卷继续由独立 H5 承载，不属于小程序页面；地址不携带预设机构、患者或场次参数。
- 通用问卷使用现有 7 题 COPD-SQ，服务端统一计分，`totalScore >= 16` 标记高危。
- 通用问卷增加服务机构选择项；只返回可用机构的公开 ID 和名称，提交时校验机构存在且启用。
- 当前尚未完成轮测闭环前，先隐藏小程序中的“设备中心”和“体脂秤”入口。页面和 BLE 代码保留，便于后续重新开放。
- 准备一名确诊慢阻肺测试患者：姓名“测试患者”、手机号 `18696144935`、身份证号 `429004199102162952`。身份证校验有效，派生性别男、生日 1991-02-16。
- 测试患者只模拟档案、COPD-SQ、确诊、随访及必要的非手环业务数据；不得插入手环绑定、手环测量、手环告警、手环状态或 IoT 上传批次数据。

## 采用方案

采用“测试场次 + 患者队列 + 医生叫号 + 结果确认”方案。

不采用队首患者自动入库，因为患者实际站秤顺序可能变化，直接写入会造成医疗数据串档。也不采用每次测量重新扫码，因为多人轮测时操作重复且容易阻塞现场。医生只需执行“下一位”和“确认结果”，既保留人工核对，又不需要搜索全机构患者。

## 角色与页面

### 医生端

医生通过现有 CDMS 账号密码登录原生小程序。体脂秤场次页承担以下职责：

1. 扫描并连接花潮 AiLink 体脂秤。
2. 创建本机构测试场次并生成短时有效签到二维码。
3. 展示候测人数、当前患者和已完成数量。
4. 对队首患者执行叫号、跳过、重新排队或取消。
5. 接收当前设备测量结果并形成待确认草稿。
6. 核对当前患者与测量结果后确认入库。
7. 关闭场次并使签到码立即失效。

### 患者端

患者登录后在首页使用“扫一扫”：

1. 扫描医生场次二维码。
2. 服务端校验场次、机构、登录角色和 `patientRef`。
3. 已建档患者看到本人脱敏摘要，确认后加入候测队列。
4. 页面展示排队号、前方人数、等待/叫号/完成状态。
5. 未关联档案时显示“未找到患者档案，请先完成建档问卷”，展示通用问卷地址并提供复制按钮，不加入队列。

## 场次和队列状态

测试场次状态：

- `OPEN`：可签到、可轮测。
- `CLOSED`：医生主动结束，不再签到或写入新结果。
- `EXPIRED`：超过有效时间，由服务端拒绝后续操作。

患者队列状态：

- `WAITING`：已签到，等待叫号。
- `CALLED`：当前唯一被叫号患者。
- `MEASURING`：已向体脂秤下发该患者性别、年龄和身高参数。
- `RESULT_PENDING`：收到完整测量数据，等待医生确认。
- `COMPLETED`：医生确认，正式测量记录已写入。
- `SKIPPED`：暂时跳过，可重新排队。
- `CANCELLED`：患者或医生取消本次签到。

同一场次最多只能有一个 `CALLED`、`MEASURING` 或 `RESULT_PENDING` 患者。患者在同一开放场次重复扫码返回原排队状态，不新增重复记录。

## 二维码与安全

二维码只包含不透明的场次签到令牌，不放患者、医生、机构或设备明文信息。令牌与场次 ID、机构 ID、创建医生、有效期和随机 nonce 绑定，关闭场次后立即失效。

所有医生操作校验医生身份及机构范围。患者签到只使用令牌中的场次上下文和登录令牌中的 `patientRef`。跨机构患者不得加入场次；前端传入的任何患者 ID 都不作为授权依据。

## 体脂数据处理

体脂秤 BLE 通道继续由独立 `ScaleBle` 管理，不复用或修改指环 `bleManager` 状态。

医生叫号后，系统用患者档案中的性别、年龄和身高配置体脂秤。设备数据到达时先保存为场次测量草稿，草稿关联当前队列项但不更新患者档案，也不写正式监测记录。

医生确认后，在一个数据库事务中：

1. 校验场次仍开放、队列项仍是当前患者、草稿未被确认。
2. 写入正式体脂测量指标。
3. 更新患者最新身高、体重和 BMI；其他体脂指标保留在测量记录中。
4. 将队列项置为 `COMPLETED`，草稿置为已确认。
5. 自动选择下一名 `WAITING` 患者，但仍需医生点击叫号后才进入测量状态。

无当前患者、状态冲突或数据不完整时，设备结果进入本场次异常草稿区，不自动绑定患者。医生可丢弃异常草稿或在当前患者明确后重新测量，不允许直接从全机构患者中任意补绑。

## 通用建档问卷

通用地址使用固定公开路由，例如 `https://jq.mockr.com.cn/mzf-sq/#/screen`，URL 不携带 `org` 或一次性机构令牌。

页面先加载启用机构的公开选项，患者选择服务机构后填写基本资料和现有 COPD-SQ。提交接口校验机构状态、身份信息、答案选项和 BMI，复用现有 `matchOrCreate`、服务端计分及筛查记录写入逻辑。提交成功后提示患者返回小程序重新登录；小程序不会自动嵌入、回跳或携带场次状态。

## 入口屏蔽

第一阶段只从患者和医生工作台配置中移除“设备中心”入口，并移除/隐藏任何指向体脂秤页面的可见入口。`pages/device`、`pages/device-scale`、体脂秤 BLE 服务、指环页面和指环服务代码均不删除。直接访问尚未开放的体脂秤页面时增加功能开关守卫，提示“功能准备中”，避免仅隐藏按钮后仍可从历史路径进入。

## 测试患者数据

测试数据写入测试环境 `cdms_followup`，使用幂等脚本或受控服务接口：

- 执行前按身份证号和手机号分别查询，身份证已有记录时复用且核对姓名；手机号属于其他身份证时停止，不覆盖。
- 患者归属机构必须显式选择一个启用的测试机构，不使用全局或空机构。
- 创建或补齐患者主档案、COPD 专档、一次 COPD-SQ 高危筛查记录、一次状态为已确诊的诊断记录，以及少量非设备随访/评估数据。
- 不创建 `cdms_patient_account` 的伪造微信身份；患者登录关联必须通过真实微信登录流程完成。
- 不写 `cdms_device_binding`、`cdms_device_measurement`、`cdms_patient_monitor_status`、`cdms_monitor_alert`、IoT 上传批次或任何手环设备记录。
- 所有写入放在单事务内，并记录新建或复用的主键。执行前备份受影响数据库，执行后核对身份证唯一、确诊状态、机构归属和手环相关记录数为零。

## 错误处理

- 场次令牌无效或过期：提示重新扫描医生当前签到码。
- 患者未建档：阻止签到并展示通用问卷地址。
- 患者跨机构：提示当前场次不属于患者所在机构，联系医生处理。
- 设备断开：保留当前队列项，医生重连后重新开始测量，不生成空结果。
- 重复测量通知：以场次、队列项和测量草稿幂等键去重。
- 医生重复确认：返回已完成结果，不重复写测量记录。
- 关闭场次仍有未确认结果：必须由医生确认丢弃或返回继续处理，不静默写入。

## 验证范围

自动化验证包括：

- 小程序入口屏蔽和直接路由守卫。
- 患者无 `patientRef` 时不能签到且能复制通用问卷地址。
- 已建档患者重复扫码幂等、跨机构拒绝、过期场次拒绝。
- 单场次只能存在一个当前患者。
- 无当前患者的测量数据不能写入正式表。
- 医生确认后正式测量、患者数据更新和队列完成必须原子提交。
- 重复确认不重复写数据。
- 通用问卷无机构参数，机构选择和机构状态由服务端校验。
- 测试患者确诊数据存在，全部手环相关记录为零。
- 现有指环测试和 JavaScript 语法检查继续通过。

蓝牙真机验收包括：连接体脂秤、两名以上患者连续扫码排队、叫号、轮流测量、医生确认、跳过/重测、断线重连，以及指环原有全流程不受影响。

## 本阶段不包含

- 在小程序内实现建档或 COPD-SQ 页面。
- 通过 WebView 打开建档问卷。
- 未建档患者直接参加体脂测试。
- 多台体脂秤并行共享一个场次。
- 自动把无法归属的测量结果绑定到任意患者。
- 伪造手环数据、微信身份或真实设备绑定。
