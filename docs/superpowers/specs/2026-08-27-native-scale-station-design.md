# 全量原生小程序约束与体脂秤轮测场次设计

## 目标

在同一个微信原生小程序中，为医生提供花潮 AiLink 身高体脂秤轮测场次，为已建档患者提供登录后扫码签到能力。系统必须支持多名患者依次测量，避免医生在全机构患者中搜索，也避免体脂数据串档。现有指环 BLE、绑定、同步和真实测试链路不得改变。

## 产品级全原生要求

本规格属于 CDMS 小程序全量原生化路线的一部分。以下要求是后续患者管理、随访、监测、报告和设备阶段共同遵守的上位约束：

- `cdms-weixin` 是移动端唯一发布工程和主要实施仓库。正式业务链路不得使用 H5 或 WebView 承载患者列表、患者档案、患者 360、随访、监测、消息、统计、AI 报告或设备工作站。
- 通用公开建档问卷是唯一允许保留的外部 H5 例外。小程序只展示或复制公开地址，不通过 WebView 嵌入，也不在 URL 中携带登录令牌、患者、机构或场次上下文。
- 全量原生范围包括医生端和患者端业务工作台、患者管理、患者 360、随访、监测告警、消息、统计、AI/标准报告、指环、医生设备工作站、MFA-1、体脂秤和 Sunvou 报告查询。
- 当前服务端功能视为业务事实和数据规则的主要来源。优先复用既有接口、权限、数据表、设备协议和报告同步能力；只有存在小程序平台不兼容、授权缺口、性能问题或幂等缺口时才新增或调整服务端契约。
- 小程序不得复制服务端计分、身份归属、机构范围、设备授权、报告匹配或临床状态等权威业务规则。客户端只负责交互校验和展示，最终校验始终由服务端执行。
- `cdms` 继续承担登录身份、角色、机构和患者业务授权；`cdms-iot` 继续承担设备、采集会话、测量、预警、报告和同步任务；`cdmsManager` 继续承担设备配置、运维和未匹配报告处理，不进入普通小程序用户主链路。
- 所有雪花 ID、患者引用、机构 ID、任务 ID、报告 ID 和设备会话 ID 在小程序中按字符串处理，禁止经过 JavaScript `Number` 转换。
- 患者个人信息、微信标识、令牌、设备密钥和报告短时地址不得写入 URL、普通日志、埋点或错误提示。

## 原生视觉体系

全量原生页面以当前 `cdms-weixin` 患者工作台为视觉权威源，具体基线为 `miniprogram/app.wxss`、`miniprogram/pages/home/home.*` 及现有原生设备卡片，不以旧 CDMS H5 的 CSS 或 Vant 组件为视觉基准。旧 H5 只作为业务字段、流程、状态和校验行为的参考。

- 沿用患者工作台现有绿色主色、浅灰绿色页面背景、白色圆角卡片、柔和阴影、胶囊状态、表单输入和标题层级。
- 公共视觉值和状态样式集中维护在 `miniprogram/app.wxss` 与原生公共组件中，业务页面不得各自定义近似但不一致的颜色、圆角和间距。
- 建立原生 Header、角色工作台卡片、患者卡片、统计卡片、状态标签、表单分组、单选/多选块、空状态、错误状态、加载骨架和底部操作栏组件。
- 医生端和患者端使用同一视觉语言，通过内容、权限和工作台结构区分角色，不建立两套主题。
- 适配微信导航栏、安全区、键盘顶起、长表单滚动、下拉刷新和不同屏幕宽度；不得为了像 H5 而破坏微信原生交互习惯。
- 视觉验收采用当前患者工作台与新增原生页面的逐页截图矩阵，检查颜色、圆角、卡片、表单、信息层级、状态反馈和触控尺寸。

## 持续登录与退出

- 登录成功后保存可轮换的 Refresh Token、身份 ID、可用角色和最近使用角色；短期 Access Token 优先保存在运行内存中。
- 小程序重新启动、微信进程被回收或手机重启后，启动流程使用 Refresh Token 静默恢复会话并进入最近使用的角色工作台。
- Access Token 过期或接口首次返回 401 时，客户端使用单例刷新锁执行一次刷新；并发请求等待刷新完成后各自重试一次，禁止产生刷新风暴或无限重试。
- 网络断开、超时、网关 5xx 或微信请求失败不得清除本地登录状态。页面展示离线或服务暂不可用状态，网络恢复后继续静默续期。
- 客户端只有用户明确点击“退出登录”时才主动清除持久登录状态。身份切换只清理角色相关的患者、检测任务和设备会话上下文，不退出账号。
- 点击退出后，无论服务端注销请求成功还是网络失败，本地登录凭据均立即清除；同时停止当前采集、断开设备、清理当前患者和任务上下文，并返回登录页。
- 管理员禁用账号、撤销角色、修改凭据或服务端吊销令牌时允许强制重新登录。这属于服务端安全控制，不视为客户端主动清除登录状态。
- Refresh Token 必须轮换；旧 Refresh Token 在成功换发后失效。角色切换和退出操作必须使不再有效的角色 Access Token 无法继续访问数据。

## 采用方案

采用“测试场次 + 患者队列 + 医生叫号 + 结果确认”方案。

不采用队首患者自动入库，因为患者实际站秤顺序可能变化，直接写入会造成医疗数据串档。也不采用每次测量重新扫码，因为多人轮测时操作重复且容易阻塞现场。医生只需执行“下一位”和“确认结果”，既保留人工核对，又不需要搜索全机构患者。

## 角色与页面

### 医生端

医生通过现有 CDMS 账号密码登录原生小程序。体脂秤场次页承担以下职责：

1. 扫描并连接花潮 AiLink 体脂秤。
2. 创建本机构测试场次并生成短时有效签到二维码。
3. 展示候测人数、当前患者和已完成数量。
4. 对队首患者执行叫号、跳过、重新排队或取消。
5. 接收当前设备测量结果并形成待确认草稿。
6. 核对当前患者与测量结果后确认入库。
7. 关闭场次并使签到码立即失效。

### 患者端

患者登录后在首页使用“扫一扫”：

1. 扫描医生场次二维码。
2. 服务端校验场次、机构、登录角色和 `patientRef`。
3. 已建档患者看到本人脱敏摘要，确认后加入候测队列。
4. 页面展示排队号、前方人数、等待/叫号/完成状态。
5. 未关联档案时显示“未找到患者档案，请先完成建档问卷”，展示通用问卷地址并提供复制按钮，不加入队列。

## 场次和队列状态

测试场次状态：

- `OPEN`：可签到、可轮测。
- `CLOSED`：医生主动结束，不再签到或写入新结果。
- `EXPIRED`：超过有效时间，由服务端拒绝后续操作。

患者队列状态：

- `WAITING`：已签到，等待叫号。
- `CALLED`：当前唯一被叫号患者。
- `MEASURING`：已向体脂秤下发该患者性别、年龄和身高参数。
- `RESULT_PENDING`：收到完整测量数据，等待医生确认。
- `COMPLETED`：医生确认，正式测量记录已写入。
- `SKIPPED`：暂时跳过，可重新排队。
- `CANCELLED`：患者或医生取消本次签到。

同一场次最多只能有一个 `CALLED`、`MEASURING` 或 `RESULT_PENDING` 患者。患者在同一开放场次重复扫码返回原排队状态，不新增重复记录。

## 二维码与安全

二维码只包含不透明的场次签到令牌，不放患者、医生、机构或设备明文信息。令牌与场次 ID、机构 ID、创建医生、有效期和随机 nonce 绑定，关闭场次后立即失效。

所有医生操作校验医生身份及机构范围。患者签到只使用令牌中的场次上下文和登录令牌中的 `patientRef`。跨机构患者不得加入场次；前端传入的任何患者 ID 都不作为授权依据。

## 体脂数据处理

体脂秤 BLE 通道继续由独立 `ScaleBle` 管理，不复用或修改指环 `bleManager` 状态。

医生叫号后，系统用患者档案中的性别、年龄和身高配置体脂秤。设备数据到达时先保存为场次测量草稿，草稿关联当前队列项但不更新患者档案，也不写正式监测记录。

医生确认后，在一个数据库事务中：

1. 校验场次仍开放、队列项仍是当前患者、草稿未被确认。
2. 写入正式体脂测量指标。
3. 更新患者最新身高、体重和 BMI；其他体脂指标保留在测量记录中。
4. 将队列项置为 `COMPLETED`，草稿置为已确认。
5. 自动选择下一名 `WAITING` 患者，但仍需医生点击叫号后才进入测量状态。

无当前患者、状态冲突或数据不完整时，设备结果进入本场次异常草稿区，不自动绑定患者。医生可丢弃异常草稿或在当前患者明确后重新测量，不允许直接从全机构患者中任意补绑。

## 通用建档问卷

通用地址使用固定公开路由，例如 `https://jq.mockr.com.cn/mzf-sq/#/screen`，URL 不携带 `org` 或一次性机构令牌。

页面先加载启用机构的公开选项，患者选择服务机构后填写基本资料和现有 COPD-SQ。提交接口校验机构状态、身份信息、答案选项和 BMI，复用现有 `matchOrCreate`、服务端计分及筛查记录写入逻辑。提交成功后提示患者返回小程序重新登录；小程序不会自动嵌入、回跳或携带场次状态。

## 入口屏蔽

第一阶段从医生工作台配置中移除“设备中心”入口，并移除/隐藏任何指向体脂秤页面的可见入口；患者端“设备”页和指环入口必须保留，保证手环真实验收。`pages/device`、`pages/device-scale`、体脂秤 BLE 服务、指环页面和指环服务代码均不删除。直接访问尚未开放的体脂秤页面时增加功能开关守卫，提示“功能准备中”，避免仅隐藏按钮后仍可从历史路径进入。

## 错误处理

- 场次令牌无效或过期：提示重新扫描医生当前签到码。
- 患者未建档：阻止签到并展示通用问卷地址。
- 患者跨机构：提示当前场次不属于患者所在机构，联系医生处理。
- 设备断开：保留当前队列项，医生重连后重新开始测量，不生成空结果。
- 重复测量通知：以场次、队列项和测量草稿幂等键去重。
- 医生重复确认：返回已完成结果，不重复写测量记录。
- 关闭场次仍有未确认结果：必须由医生确认丢弃或返回继续处理，不静默写入。
